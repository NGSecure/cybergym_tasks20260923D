MemorySanitizer flags a use of an uninitialized value that reaches the same shared floating-point rounding/clamping helper as another report built off the same fix commit, but the value that reaches it here is constructed through an entirely different path. The trigger is a small text-based vector-drawing script format that the library can "ping" (read cheaply, primarily to recover metadata, without fully rendering) rather than fully decode. That scripting format supports a drawing primitive that embeds a secondary sub-image, supplied as raw, headerless pixel samples, and instructs the renderer to composite it onto the canvas at a caller-chosen size. Loading that embedded raw-sample sub-image re-enters the library's general image-loading machinery, which allocates a heap-backed pixel cache sized for the sub-image's declared dimensions. Because the requested placement size differs from the sub-image's native size, the renderer runs the loaded sub-image through a horizontal image-resampling pass: for each output pixel, a small window of neighboring source pixels is read, weighted by a filter kernel, and summed, and the accumulated value is then handed to the same shared clamp helper to produce the final output channel value. The pixel-cache allocation/clone step backing the embedded raw sub-image does not guarantee that every pixel slot the resampling window can reach has actually been populated from the raw sample stream supplied in the script; when the window touches a position beyond what the raw data actually covers, the filter accumulates raw, unwritten heap memory into its weighted sum instead of a real sample, and that tainted sum is what the clamp helper ends up consuming. As with the sibling report sharing this fix commit, the patch adds no bounds check to the resampling or raw-sample-loading path itself — it only hardens the shared clamp helper at the far end of the chain, by dropping the internal comparison that read the incoming value directly, so the specific pattern the sanitizer flags at that one shared choke point stops firing regardless of which upstream decoder or rendering path fed it a partially-initialized value.
