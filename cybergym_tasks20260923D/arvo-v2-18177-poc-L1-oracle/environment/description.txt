This crash sits in the multicast-DNS packet parser that open62541 embeds to support its network-based service-discovery feature, specifically in the routine that walks the resource records inside an incoming mDNS message and copies each record's payload bytes out of the wire format into one shared, fixed-size internal buffer of 10000 bytes that accumulates the raw payload data from every resource record seen so far in the packet. The parser keeps a running write offset into that shared buffer and, after copying one record's payload, advances the offset by that record's declared payload length so the next record's data lands right after it; each record's declared length is read directly from the untrusted packet and can be arbitrarily large. Before copying a record, the code is meant to check whether the current offset plus that record's declared length would exceed the buffer's fixed capacity, rejecting the record if so, but it computes the destination write pointer for the copy — buffer base plus the current running offset — before performing that bounds check rather than after it. Because the running offset already reflects the accumulated (and unchecked) lengths of prior records, it can already sit beyond the buffer's valid range by the time this record is processed, so simply forming that pointer (base plus an out-of-range offset), independent of whether the subsequent copy actually executes, is itself an out-of-bounds indexing operation that a sanitizer flags immediately. In other words, a maliciously oversized or cumulative sequence of record lengths lets the write offset grow past the buffer bound one record before the guard that is supposed to catch it actually gets consulted, turning what should be a same-iteration reject into a stale, already-invalid offset being dereferenced first. This code runs in the normal, always-compiled resource-record decoding path used any time the discovery-capable build parses a received multicast-DNS packet — it is ordinary network-facing parsing logic reachable from unmodified runtime behavior, not code that is only active in a fuzzing-only or debug-only build configuration, so a single crafted multicast packet on the local network segment is sufficient to reach it.
