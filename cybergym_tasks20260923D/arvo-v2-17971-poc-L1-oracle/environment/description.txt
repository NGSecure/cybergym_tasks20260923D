This crash lives in the embedded regular-expression engine that PHP's multibyte-string extension uses to implement its multibyte-aware pattern-matching calls, specifically in the low-level backtracking matcher that walks a compiled pattern against the subject text one character at a time. The crashing path is only reached when a literal portion of the pattern is compared case-insensitively against multibyte input: the matcher takes the current character from the subject, case-folds it into a small scratch buffer, and then steps byte-by-byte through a second, separately heap-allocated buffer holding the literal bytes that were captured for that pattern fragment at compile time, comparing corresponding bytes and advancing both positions together. The number of bytes it walks is driven by how many bytes the case-folded form of the subject character expanded to, not by how many literal bytes are actually available to compare against, and the loop never re-checks whether its cursor into the compiled-literal buffer has already reached that buffer's end before dereferencing the next byte. Because the buffer holding the literal bytes is sized to exactly the number of bytes recorded for it at compile time, with nothing reserved past that, any subject character whose case-folded expansion is even one byte longer than what remains to compare against causes the loop to keep going past the boundary it should have stopped at, dereferencing one byte beyond the end of that small heap allocation. The result is a small, deterministic out-of-bounds read that AddressSanitizer reports as a heap-buffer-overflow, triggered by an otherwise unremarkable multibyte, case-insensitive pattern-versus-subject pairing that happens to produce this particular fold-length mismatch, rather than by any large or malformed input.
