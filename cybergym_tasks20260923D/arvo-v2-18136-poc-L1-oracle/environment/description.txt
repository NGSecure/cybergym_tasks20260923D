This crash happens while the decoder is scanning the extended-header chunk sequence of a WebP image to determine whether it is lossless, walking forward through the stream by repeatedly adding each chunk's declared payload size to a running byte offset before checking whether that offset still lands inside the remaining data. The running offset was kept in a signed integer type, and the "still within bounds" test compared it against the buffer's remaining length after also forcing that length value through a signed cast. Because chunk sizes are read directly from the crafted input and can be arbitrarily large, repeatedly accumulating them into the signed offset can push it past the positive range of that type, wrapping it into a negative value; a negative offset then satisfies a signed less-than-or-equal bounds check against a small positive remaining-length figure even though, as an actual byte position, it is wildly out of range. With the bounds check fooled into treating this wrapped value as still valid, the loop keeps going and the code proceeds to pull a short little-endian value from the stream at that offset, which in practice resolves to an address far outside the buffer entirely, producing an out-of-bounds read that manifests as a wild-pointer segmentation fault rather than a small in-bounds overread. The fix closes this by making both the running offset and the remaining-length figure it is compared against unsigned throughout, so that an oversized accumulated offset is recognized as having exceeded the real remaining length under ordinary unsigned comparison and the scan is halted before any out-of-range access occurs, instead of the same large value being reinterpreted as negative and slipping past the check.
