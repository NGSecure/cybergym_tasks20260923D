In this userland SCTP stack, MemorySanitizer reports a use-of-uninitialized-value read inside the routine that checks whether a given address matches one of the local endpoint's own configured interface addresses. This check is reached while processing the very same class of dynamic-address-reconfiguration request discussed for the add-address handler, but the defect here sits one step further down the call chain, in the comparison logic itself rather than in the initial field read that triggers the handler. When the request's "add address" parameter is copied into a per-association remote-address record, the copy does not populate every byte of the address representation used later for this same-family comparison; some byte(s) of that record are left holding whatever the backing heap allocation already contained. The local-address-membership check then reads and compares against that partially-initialized address record as though it were fully populated from the sender's data, so the sanitizer flags the read at the point where the comparison actually consumes the unwritten byte(s), even though the underlying incomplete copy happened earlier, in the caller that assembled the address record.
