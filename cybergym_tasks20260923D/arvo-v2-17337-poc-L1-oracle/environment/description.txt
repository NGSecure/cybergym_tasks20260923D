This proof-of-concept is another malformed HDF5-based MAT file that exercises the same underlying class of corrupted local-heap bookkeeping as a related crash in this same reader, but it reaches the bad memory access through a different, deeper path. Here the group's directory is well-formed enough that the initial entry-by-entry enumeration of the file's top-level variables completes successfully; the crash instead occurs when the reader performs a second, follow-up lookup for one of the already-enumerated members -- searching the group's internal binary-tree index by name to fetch that member's additional object metadata. That search descends the tree comparing the target name against each node's stored key, and one of those stored keys is, once again, resolved through a heap-relative offset that the corrupted free-list bookkeeping leaves pointing outside the heap's actual allocated buffer. The consequence is a wild out-of-bounds read, but this time it happens partway through a byte-by-byte name comparison rather than during the initial construction of a name string, and it can only be reached after the first enumeration pass succeeds and triggers a name-based re-lookup for a specific member -- a later and more specific trigger condition than a crash that fires on the very first directory entry.
