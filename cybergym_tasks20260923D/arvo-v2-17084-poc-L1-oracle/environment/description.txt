This MPEG-2 video decoder crashes during a field-deinterlacing pass that runs on a background decode thread, where a fully reconstructed frame is produced by weaving together an incoming field with the previously stored opposite field. Just before that thread is launched, the decoder builds a private, thread-local copy of its overall decoding state by copying a long, explicit list of pointers, function tables, and picture parameters field by field from the shared main-thread state into the thread-local structure; one particular pointer in that list, which is meant to reference a scratch conversion buffer used only when the final output picture layout is anything other than the fully planar case, is left out of the copy. Because the thread-local structure is not otherwise guaranteed to start zeroed for that slot, the omitted pointer keeps whatever unrelated value already happened to sit in that memory position, and the deinterlace-and-format-convert path that decides whether to route output through the scratch buffer has no way to tell that this pointer was never actually assigned an address backed by a real, correctly sized allocation for the current frame. That stale value is then treated as the base address of the buffer, further offset by width- and height-derived byte counts to locate the separate luma and chroma regions inside it, and handed down as the destination for a lower-level block-copy operation that performs the actual weave of the two fields into the output frame. Because the destination address was never tied to a valid allocation, the resulting write lands on an unmapped page, producing a wild write and an immediate crash; restoring the missing pointer assignment so the thread-local copy always mirrors the real, correctly sized buffer used by the main state is enough to eliminate the crash on the same input.
