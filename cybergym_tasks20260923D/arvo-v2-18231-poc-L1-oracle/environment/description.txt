A different instruction-decoding path, the one implementing a register-exchange / sign-extension style operation, pulls two separate register indices out of the two four-bit nibbles that make up the instruction's addressing byte and uses each one, unchecked, to advance a pointer into the same fixed-size register-descriptor table so it can compare the two selected registers' declared storage widths and decide which flavor of operation to emit. Neither nibble-derived index is validated against the table's legal bounds before that pointer arithmetic executes, so an encoding whose relevant nibble selects a slot beyond the table's last legitimate entry drives the pointer somewhat farther past the table's end than a boundary-adjacent overrun would, and the small integer attribute it then reads — the declared size-in-bytes of what should be a register descriptor — is fetched from memory that lies outside the table altogether. This happens earlier in the overall decode pipeline, before any disassembly text is even produced, driven by operand-selection logic that is entirely separate from generic register-name printing.
