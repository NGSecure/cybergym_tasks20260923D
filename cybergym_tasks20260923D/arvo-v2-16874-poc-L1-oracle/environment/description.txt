When this library parses a MATLAB level-4 (v4) sparse-matrix variable, it reads a temporary scratch array of column-index markers directly from the file, sized from an earlier row-count field, and then uses that scratch array to derive per-column start offsets for the sparse structure's real, separately-allocated column-bookkeeping array (sized instead from a column-count field). The derivation walks the scratch array with an advancing cursor, looking for the first marker exceeding each successive column number, and writes the resulting cursor position into the corresponding slot of the real column array. The scratch array's fill step from the file never checks whether it actually received as many elements as it was sized to hold; when the file is short or otherwise malformed so that fewer usable integers are actually written into the scratch array than its allocated capacity, the unwritten tail is left holding arbitrary leftover heap bytes rather than the marker values the derivation logic expects. Because the derivation's cursor advances by comparing against whatever value happens to sit in that unwritten tail, garbage markers there can let the cursor advance further, or in a different pattern, than any well-formed file would ever produce, and the resulting cursor value written into the real column array's next slot can then fall outside that array's own separately-sized allocation, producing a small out-of-bounds heap write one element past its true end. The missing piece is a check, right after the scratch array's fill step, that the number of elements actually read from the file matched the number the scratch array was allocated for, before any of it is trusted to drive the column-offset derivation.
