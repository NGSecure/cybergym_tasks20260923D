This is a stack out-of-bounds read that happens while the library parses a zlib-compressed variable header inside a MAT-file. After inflating the initial tag and rank/dimension-count words, the parser reuses a small, fixed-size on-stack scratch buffer to hold the following dimension words whenever a helper decided the dimension data was compact enough not to need a separate heap allocation; in that fallback case, a raw pointer into the scratch buffer -- already advanced past the two words consumed by that rank/dimension tag -- is treated as the start of the dimension array. The number of dimensions (the variable's declared rank) is derived directly from an attacker-controlled 32-bit byte count taken from the compressed stream and divided by four, and in this fallback, reused-scratch-buffer case nothing checks that rank against anything at all before it is used to size the copy loop below -- there is no bound of any kind on this path, let alone one keyed to how many scratch-buffer words actually remain. As a result, a crafted rank that is modest enough to have avoided the helper's separate-allocation path, yet larger than the words actually left in the reused scratch buffer, makes the per-dimension copy loop read one extra 32-bit word beyond the buffer's end on its final iteration -- an out-of-bounds stack read that shows up immediately adjacent to the buffer's other local variables. The fix closes this gap by rejecting any declared rank above a small fixed ceiling whenever the dimensions are still being read out of the reused scratch buffer rather than a freshly allocated array, bailing out with an error instead of letting the copy proceed past the buffer's true capacity.
