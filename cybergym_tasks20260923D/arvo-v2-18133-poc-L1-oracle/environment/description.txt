MemorySanitizer flags a use of an uninitialized value while the library is decoding a raster image stored in one of its older scientific/interchange raster-image formats. After the format-specific reader allocates a per-scanline pixel buffer sized according to the number of color/data components the file's header declares, it fills that buffer by pulling fixed-width samples out of the file and byte-swapping each one into the platform's native order. A later, format-independent pass then walks every pixel of the freshly decoded image to normalize its color values into the library's internal representation, converting each channel through a small floating-point rounding/clamping helper that is shared by essentially every image coder in the library. The gap is a mismatch between how many bytes per pixel the format-specific reader actually populates for a given file (driven by a header field describing the file's storage/component layout) and how many channel values the later normalization pass reads back out of that same buffer; when a crafted file declares a layout that causes fewer bytes to be written than are later consumed, the tail of the per-pixel buffer is left holding raw, never-written heap memory, and that memory reaches the shared clamp helper during normalization, which is where the sanitizer trips. The fix does not touch the format-specific reader at all. Instead it hardens the shared clamp helper itself, dropping an internal range comparison that evaluated the incoming (possibly not-fully-initialized) floating value directly before converting it, so the exact pattern the sanitizer was catching at that shared choke point can no longer fire. A related multi-byte floating-point sample-parsing routine used elsewhere in the same shared pixel-import layer is also restructured, so a byte-order-dependent read can no longer fall through between its two ordering branches, and an explicit lower/upper bound clamp is added on the parsed sample there.
