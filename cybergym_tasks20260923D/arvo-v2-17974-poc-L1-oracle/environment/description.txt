ImageMagick (MSan build): while decoding a JPEG whose APP1 metadata segment is split across multiple marker chunks belonging to the same profile, the decoder merges a newly read chunk with the previously accumulated profile buffer by growing the buffer in place and shifting/copying the chunk bytes into it. The grow step reallocates the buffer to the new combined size but does not re-clear the small guard region conventionally kept just past the logical end of the data (historically relied on to be zero from the buffer's very first allocation). After the merge, a later metadata-type detection pass scans the merged buffer as if it were a bounded, safely-terminated byte string; that scan reads into the unrefreshed guard byte, which is stale/uninitialized after the grow, producing a use-of-uninitialized-value warning. Root cause: the buffer-growth path used when concatenating profile chunks does not re-initialize the trailing guard byte the way the initial allocation does, so any code that later treats the (regrown) buffer as implicitly bounded reads uninitialized memory rather than a real terminator.
