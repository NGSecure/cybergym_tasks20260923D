A separate, differently sized per-coding-tree-block array holds the deblocking filter's vertical boundary-strength bookkeeping, and it is populated through a bulk clear rather than through individual element stores. That clearing step is reached only on a path specific to intra-coded slices, and specifically the branch that trims the clear to account for a coding-tree-block column sitting at the picture's right edge, where the true remaining picture width leaves less than one full nominal block's worth of columns still to process. The byte count handed to the bulk-clear call for that trimmed final column is derived by subtracting the (possibly small) remaining-column count from the nominal per-block clear width, under an implicit assumption that this difference always comes out non-negative; when the picture's width relative to the current column position leaves fewer remaining columns than a particular internal margin the arithmetic expects, that subtraction instead produces a small negative byte count, which is then reinterpreted as a huge unsigned length and, together with the same base position, yields an effective start address one byte before the array's true lower bound. Unlike a forward overrun past an array's end, this is an underflow immediately below the buffer's lower bound, triggered by a right-picture-edge, narrow-final-column condition rather than by anything to do with which row of coding-tree blocks is being processed; the missing safeguard is a check that this trimmed byte-count arithmetic cannot go negative before it is used to compute where the clear should start and how far it should run.
