In mruby's bison-based Ruby source parser, keyword parameters that carry a default-value expression are parsed by opening a temporary, nested local-variable scope for the duration of that default expression, so that any variable references introduced while parsing the default get tracked separately from the enclosing scope. For keyword parameters that appear in a method definition's parameter list, the parser correctly closes out this nested scope once the default expression is fully parsed: it bundles the parsed default-value node together with a snapshot of the locals captured in that nested scope into a single paired value, then restores the enclosing scope. The grammar rule that recognizes the same keyword-parameter-with-default construct when it instead appears inside a block or lambda's parameter list, however, skipped both of those steps -- it forwarded only the bare default-value expression, with no accompanying locals snapshot attached, and never restored the enclosing scope. A later, shared step that finishes assembling any parameter list's trailing keyword/rest/block section does not know which grammar rule produced each keyword parameter; for every keyword parameter that carries a default, it unconditionally treats the second half of whatever value it was handed as a proper list of locals to re-register in the surrounding scope, walking it link by link. Coming from the block/lambda path, that second half is not a locals list at all -- it is simply whatever internal field happens to sit where a list's next-pointer would be in the actual default-value expression node, since no locals snapshot was ever paired in. Walking that field as though it were a chain of symbol-bearing list cells eventually follows a value that is not a valid node address, and dereferencing it to keep walking reads from unmapped memory and crashes. The fix makes the block/lambda-parameter-default rule mirror the method-parameter-default rule exactly: it now bundles the default-value expression with a snapshot of the nested scope's locals before handing it onward, and explicitly restores the enclosing scope afterward, so the shared finalizer always receives a genuine paired (value, locals) structure to walk instead of an arbitrary expression node being misread as one.
