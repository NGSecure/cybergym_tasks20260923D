This crash occurs while decoding a signature-value structure, specifically while recursively unpacking a nested sub-field within it that is treated as an unsigned integer-like octet string. After extracting that sub-field's raw content, the post-processing step responsible for stripping a leading all-zero padding byte (added to keep a signed encoding of an otherwise-unsigned quantity non-negative) checks whether the first content byte equals zero before it confirms that the sub-field's content actually has more than one byte. When the crafted input causes that particular sub-field to decode to zero-length content, the stripping logic still reads the first, non-existent content byte to test it against zero, and that read lands one byte past the end of a small heap allocation backing the decoded value, producing a one-byte heap-buffer-overflow read under AddressSanitizer.
