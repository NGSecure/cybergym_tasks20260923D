In this userland SCTP stack, MemorySanitizer reports a use-of-uninitialized-value read while the association-management code is handling an incoming dynamic-address-reconfiguration request that asks the peer to add a new IP address to the association. The reconfiguration request arrives as a single parameter embedded in a control chunk, and the handler for the "add address" parameter reads one of that parameter's fields directly out of the freshly received packet buffer at a fixed offset, on the assumption that a full, correctly-sized parameter is always present. When the parameter actually delivered by the sender is shorter than that assumed layout (so the declared/actual parameter length does not cover the offset being read), the handler does not first confirm the parameter is long enough before consuming that field; it simply reads whatever bytes happen to sit at that offset in the backing packet buffer, which for a heap allocation that was never written that far is indeterminate content rather than data the sender actually supplied. The subsequent processing then branches on this indeterminate value as if it were a legitimate part of the request.
