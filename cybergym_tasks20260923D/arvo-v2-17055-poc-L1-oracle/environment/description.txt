libhevc's HEVC frame decoder (ASan build, main decode path): while recursively descending the coding-tree quadtree to parse an intra-predicted coding unit, the decoder records that unit's position into a per-picture bitmap flagging which regions of the frame are intra-coded, computing the starting byte from the picture's declared width together with the unit's row/column offset and then advancing through consecutive rows of that bitmap once for every group of eight luma samples spanned by the coding unit's height. This bitmap is sized once, when picture-level buffers are first allocated for a given sequence-parameter-set identifier, and the decoder does not detect the case where a later part of the same bitstream re-signals that same identifier with a different coding-tree-block size before the earlier buffers are discarded and reallocated for the new geometry; if decoding proceeds on a picture that is still using the stale, now-too-small allocation, the row count and row stride the loop walks are effectively driven by the newer, larger geometry, so a sufficiently large intra coding unit near the edge of the frame carries the loop one byte past the true end of the small allocated region, producing a heap-buffer-overflow read on the decoder's main parsing thread.
