This is a global-buffer-overflow read triggered while parsing a configuration section header. A string-append helper used throughout the config parser accepts a pointer together with an explicit length, but it overloads a length value of zero to mean "unknown, discover it yourself by scanning forward for a terminating NUL byte" rather than "append zero bytes." The section-name token produced by the tokenizer is handed to this helper without first checking whether the token is degenerate, i.e. genuinely empty, such as when a section header's delimiters contain no text between them. When that happens, the token's length really is zero, and the helper misinterprets this legitimate empty value as the "compute the length yourself" sentinel, falling back to scanning byte-by-byte from the token's start pointer in search of a NUL terminator. Because that pointer refers into the middle of a larger, non-NUL-terminated buffer holding the raw configuration text being parsed, the scan does not stop where the token semantically ends; it runs past the buffer's valid contents and past the end of the underlying storage entirely before any terminator is ever found, producing a large out-of-bounds read that overruns a fixed-size buffer. The fix closes this off by explicitly checking the section-name token's length immediately after it is extracted and bailing out with an error on a zero-length token before it is ever passed into the length-overloaded append routine, so a degenerate empty token can no longer collide with the sentinel value and trigger the unbounded scan.
