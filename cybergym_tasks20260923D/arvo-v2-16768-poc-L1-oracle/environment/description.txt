This is a heap-buffer-overflow read inside an animated-image loader that tracks a small per-frame array of timing values alongside a running count of frames decoded so far. The array is grown (via reallocation) only at the moment an optional, frame-associated metadata block happens to be parsed, with the resize check keyed off comparing the current frame tally against the array's already-allocated length; growth is not tied directly to the frame tally advancing on its own. When a frame arrives without that optional metadata block present, or more generally whenever the two counters can drift apart on a malformed or adversarially crafted input, the frame tally can outpace the array's allocated capacity, so the timing array ends up smaller than the number of frames actually counted. Later, once decoding finishes, the loader packages the per-frame timing values into an output array sized according to the final frame tally and copies that many integers out of the (now undersized) buffer in one bulk copy — reading one or more elements past the end of the true allocation rather than writing beyond it. The underlying fix decouples the array's growth from the incidental metadata-block event entirely and instead ties reallocation directly and unconditionally to every increment of the frame tally (including ensuring the array already has a nonzero initial allocation before any frame is processed), so the array's capacity can never lag behind the count later used to size the read-out, regardless of which optional blocks a given frame does or doesn't carry.
