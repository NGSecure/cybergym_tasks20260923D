This is a heap out-of-bounds read triggered while the image library's TIFF-reading path inspects an embedded XMP-style metadata block during a lightweight, header-only pass over the file, purely to decide whether the picture should be treated as one particular camera-raw variant. The routine obtains a raw pointer to that metadata payload together with a byte count that an internal tag-parsing helper reports for it, but then hands the pointer straight to a classic C substring search that has no notion of an explicit end and instead keeps advancing until it hits a NUL byte. The byte count that sized the underlying heap allocation reflects only what the file's own tag declared for that payload; nothing upstream guarantees a NUL terminator actually falls inside those bounds before the search runs. When a crafted file supplies a payload with no such terminator, the search marches straight off the end of the small allocation and keeps reading, one byte at a time, for thousands of bytes into adjacent heap memory that was never part of the intended buffer, until it either stumbles on a false match or crashes against an unmapped or poisoned region. In short, attacker-controlled, tag-length-bounded binary data is passed to a string primitive that assumes NUL-termination instead of trusting the already-known explicit length, letting a short, degenerate (unterminated) payload turn a bounded lookup into an unbounded overrun. The fix removes the assumption entirely: the payload is first copied into an explicitly length-bounded string object before the substring search runs, so the search is now capped at the declared payload size and can never walk past it, regardless of whether a NUL byte ever appears in the data.
